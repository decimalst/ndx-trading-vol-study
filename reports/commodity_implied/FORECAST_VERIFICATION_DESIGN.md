# Prospective independent commodity forecast verification

This independent verifier is specified with generated tests before implementation and before access to actual commodity/market feature rows, cohorts, fits, outcomes or predictions. No source-admission artifacts or previously frozen code are modified. The only historical implementation reuse permitted is the pinned independent claims verifier's loop-based `_market_targets` and numerical/schema comparator `_compare`; the new verifier never calls a producer to establish expectations.

`verify_forecasts(daily, cross, iv, commodity_iv, config, produced)` accepts full raw input calendars, the exact commodity pipeline config, and the five-key successful pipeline payload. All four input date envelopes and exact schemas are checked before numeric reconstruction, including dates outside the QQQ reference calendar. Calendars are unique ordered naive midnight native datetime indexes, nanosecond representable, with source-end and fixed 2025-10-20 ceilings. The commodity IV table has uppercase OVX/GVZ columns. No source hash or original-vintage admission is inferred from this numerical API.

The checker independently reconstructs the ten commodity regressors and prior-session commodity cutoff. Reindexing precedes the one-full-session delay; both prices and implied vol before 2009-01-02 are masked before conversion. Commodity price log returns and their squares feed strict five/22-position arithmetic means and logarithms. Missing dates/values never compress or fill windows; all-zero windows remain unknown. Nonzero squared-return underflow/overflow fails. Implied volatility converts directly by `2*(log(index)-log(100))-log(252)`, preserving finite logarithms for extreme positive levels.

The complete 22-feature intersection governs all arms, application selection and training. The first feature-complete requested origin in each month establishes its fit, independent of the query's target. Training labels must end by the immediately preceding full observed session; all eligible earlier rows are required. Separate market12, matched20 and candidate22 models use training-only population scaling, scale>1e-12, rank cutoff1e-12, independent reduced-QR least squares, and separate exact training-residual Duan smearing. Every model audit, training/application origin list and forecast is reconstructed. Insufficient monthly support, rank, scale or invalid arithmetic aborts without partial acceptance.

All requested origins remain in coverage and all requested months remain in schedules. Every complete application retains predictions, including outside-phase, missing-target, phase-censored and immature-tail rows. Targets use exactly five later positions of the unchanged complete QQQ calendar. Development targets mature by development end; evaluation targets mature by source end, even when evaluation origin bounds end earlier. Offsets use full-calendar position modulo five. Complete panel rows are ordered origin then market/matched/candidate and use ordinary positive-ratio QLIKE.

The verifier compares all five output schemas, order, dates, identities, counts, missingness, fit links and censoring fields. Numerical tolerances follow the frozen claims verification convention: coefficient absolute/relative 1e-7; forecasts absolute1e-12/relative1e-7; other numerical audits absolute1e-12/relative1e-9. Dates, identities and counts are exact. These tolerances are fixed before generated agreement and any historical run.

Prewritten tests include scalar commodity feature and unscaled QR numerical oracles; floor, missing-calendar, causal mutation and extreme-value checks; all-four-calendar preflight before arithmetic; generated producer/checker agreement and JSON audit transport; ms/us/ns calendars; corruption of every output family and model audit; query-label blindness; exact common22 maturity; full-calendar offsets; unscored/censored coverage; empty/incomplete months; insufficient support/rank failure; and input preservation. Producer functions appear only in generated agreement/corruption fixtures, never in verifier expectations.

All 24 methods were written before the verifier module existed. `FORECAST_VERIFICATION_RED.log` records the actual missing-module failure. The first implementation passed all 24 methods in 23.698 seconds; both `FORECAST_VERIFICATION_FIRST_IMPLEMENTATION.log` and `FORECAST_VERIFICATION_GREEN.log` retain that same run. No numerical contract, tolerance or test expectation changed after implementation. Scoped Ruff formatting changed layout only, and lint found one unused test-fixture binding, renamed with an underscore without changing its value or use. The final scoped lint check passed. No actual source/panel/fit/outcome bytes or full repository test suite were read or run by this subtask.

The verifier imports only `math`, `re`, NumPy, pandas, and `_compare`/`_market_targets` from the pinned independent claims forecast verifier. All commodity transformations, monthly scheduling, common-row selection, QR model fitting, smearing and commodity-output reconstruction are local to the new verifier. The verification result reports VERIFIED and counts of reconstructed applications, forecasts, monthly/model fits, coverage origins and calendar rows; it makes no inference or source-vintage claim.
