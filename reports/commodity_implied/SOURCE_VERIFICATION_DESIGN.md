# Independent source history verification

This is a prospective generated-test contract for `src/verify_commodity_implied_source.py`. No quarantined Cboe history body, retained observations, market data, support counts, or forecasting results are inputs to this work. The existing 370 Python files and completed reports remain unchanged. The checker uses the standard library and never imports or calls the producer parser.

`verify_history(payload, symbol, expected_sha256, parsed, start='2009-01-02', end='2025-10-20')` independently reconstructs the entire proposed producer result, checks every field and scalar type, and returns only `status='VERIFIED'`, the symbol, and retained/observed/missing row counts. It makes no assertion of original publication vintage, historical file immutability, model readiness, or predictive value.

The payload must be bytes, match an exact lowercase SHA-256 identity, and decode as strict UTF-8 with an optional initial BOM. Symbols are exactly OVX or GVZ. The header is exactly `DATE,<symbol>`. Every nonblank CSV record has two fields. The CSV reader's ending physical line number is the source line; empty physical records are ignored, while whitespace and empty fields do not create a blank record. CSV quoting is supported, including an outside-window quoted value spanning physical lines.

All file dates are checked before `_parse_value` is called for any value. Dates accept ASCII `M/D/YYYY` with one or two digits for month/day, or exact ISO `YYYY-MM-DD`, with calendar validity, strict ascending order, and uniqueness across the entire file, including excluded rows. Date and value fields are not stripped. Requested bounds must be exact ISO dates within 2009-01-02 through 2025-10-20, inclusive, and ordered. Narrower prospective windows are allowed; before/after counts refer to the requested window. Values outside that window are neither converted nor returned, even when they contain deliberately invalid numeric sentinels.

Retained values are either exactly empty or `.` (missing with value null), or match an ASCII decimal grammar with optional sign and exponent, then convert to a finite strictly positive float. Overflow, underflow to zero, nonpositive values, NaN/infinity spellings, booleans, whitespace, separators, and non-ASCII digits fail. No filling or calendar extension occurs. A structurally valid empty retained window has zero retained counts and null first/last dates.

The independently reconstructed result has exactly the root-agreed status, symbol, raw source SHA-256, requested bounds, ordered records (date/value/status/source_line), and eight metadata fields. Every key, count, endpoint, record position, source line, null, status, and numerical float must agree exactly; booleans and integer/float aliases do not satisfy another scalar type. Unexpected keys are rejected, and inputs are not mutated.

The prewritten suite covers both symbols; original line numbers; BOM/UTF-8 and header identity; complete-file structural preflight before conversion; protected/outside sentinels; equivalent date duplicate detection; malformed and reversed future records; exact numeric lexemes and missing status; narrower and forbidden widened windows; valid empty windows; quote/blank-line behavior; raw and parsed hash tampering; missing/extra/reordered/duplicated records; every metadata field; unknown schemas; exact scalar/container types; and no mutation. Every fixture is generated in the test module without producer calls.

All 25 test methods were written before the checker module existed. `SOURCE_VERIFICATION_RED.log` records the observed missing-module import failure. The first implementation then passed all 25 methods in 0.007 seconds, recorded in `SOURCE_VERIFICATION_GREEN.log`. Scoped Ruff formatting changed only the new test file's layout; the scoped lint check passed for both new Python files. No numerical contract or test expectation changed after implementation, and no full repository suite or actual source admission was run by this subtask.

The checker imports only `csv`, `hashlib`, `io`, `math`, `re`, and `datetime.date`. It uses strict CSV parsing so malformed quoted records anywhere in the file also fail before retained-value conversion. No empirical admission is authorized by this document; original-vintage and publication-clock limitations remain as documented in `SOURCE_FEASIBILITY.md`.
