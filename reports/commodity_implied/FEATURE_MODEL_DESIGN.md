# Fixed commodity features and three OLS arms

Prospective generated component design, 2026-09-08. Tests precede implementation. No actual commodity/equity numerical sources, cohorts, fits or scores are read or constructed here. Existing sources, code and reports are preserved.

`build_commodity_features(reference_calendar, cross, commodity_iv)` retains the entire ordered naive midnight QQQ calendar. Both source calendars and the reference calendar are validated against 2025-10-20 before numerical arithmetic. Cross has the exact inherited five column names but only uso/gld values are examined; the other three columns remain opaque. Commodity IV has exact uppercase OVX/GVZ columns. Reindex to the full QQQ calendar first, mask all dates before 2009-01-02 in both new price/IV inputs before numerical conversion, then delay observations by one full reference-calendar session. Missing dates remain missing; returns and rolling windows never compress or fill the calendar.

Fixed output order is uso_ret, uso_r2, uso_lrv5, uso_lrv22, gld_ret, gld_r2, gld_lrv5, gld_lrv22, lovx, lgvz, followed by metadata commodity_cutoff_date. For each asset, ret is the lagged close-to-close log return, r2 its square, lrv5/lrv22 the log of a strict arithmetic mean of the last five/22 squared returns. The first post-floor price cannot borrow a pre-floor predecessor. Zero one-session return and square are valid; all-zero longer windows yield unknown log variance without epsilon. The audit date is the prior full QQQ session (NaT before the floor), not an assertion that a source observation exists there.

`lovx` and `lgvz` are annualized percentage volatility converted algebraically to log daily variance as `2*(log(index)-log(100))-log(252)`, after the delay. Avoid forming a tiny or huge variance before logging. Inputs require real numeric nonboolean selected columns and positive finite observed prices/IV, with NaN preserved. Nonfinite or nonzero underflow/overflow during arithmetic aborts; never convert it to a zero or silently drop that row. Strict squared-return arithmetic is separately tested at float extremes.

`fit_models(train_features, train_y, apply_features)` has market/matched/candidate predictions and fits dictionaries. MARKET is the inherited 12-name order from the completed claims model module. MATCHED appends the eight commodity-history features in uso-then-gld order (20 total); ALL appends lovx,lgvz (22 total). All22 columns must be finite on every supplied train/application row, with intercept exactly one. A caller chooses one common causal cohort; this component performs no row selection.

The new matrix validator and feature names wrap the read-only frozen generic `_targets` and `_fit_arm` helpers from claims_release_models. All three models fit log target by OLS with training-only population scaling, fixed minimum scale>1e-12 and full rank under relative cutoff1e-12. Each arm has its own exact training-residual Duan smearing. The existing coefficient, mean/scale, singular-value/rank, smearing, normal-equation and row-count audit schema is retained. No tuning, column removal, clipping or fallback is introduced.

Generated tests independently specify feature histories and boundary dates; test causal perturbations, floor invariance, missing source dates, zero returns, log-variance extreme inputs and errors before arithmetic. Model tests compare all three predictions to an independent unstandardized QR solve and reconstruct the saved audits, assert separate smearing and common22-row requirements, and test affine/unit transport and failures. Independent historical verification and source admission remain separate future components.
