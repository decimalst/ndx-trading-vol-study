## Independence and order

The entry imports the frozen independent wave20 validation, Brier arithmetic, HAC, explicit block bootstrap, Holm and numeric-comparison primitives. It does not import the new runner's inference or call either producer's forecast generator or optimizer. The complete literal typed wave21 protocol is checked before source admission; its new wave allocation, inherited family and date representation contract cannot drift through an unchecked configuration change.

The source metadata traversal is shared with `event_cluster_replay_admission`, and this shared implementation is disclosed in the proof. The entry independently checks literal anchors, all transitive manifest references and group inventories, original verified output identities, the exact six retained input paths, checked snapshots and the required failed-wave20 record. Metadata traversal is not an independent source-provenance implementation. Retained numerical reconstruction uses the same new independent mathematical helper as the runner, repeated against retained producer output; it is independent of that original producer rather than a second independently authored implementation of the replay helper.

`verify` snapshots the protocol and manifest, validates the complete code/input/preservation inventory and freeze evidence, then snapshots exactly four new outputs: upstream-admission audit, reconstruction audit, metrics and ledger. It rejects a failed new replay or incorrect metric identity. Admission returns `(proof, original_loaded, retained)` with six retained objects and unchanged original source configuration. The original index section must match exactly.

The full eleven-argument reconstruction runs before replay metric inference. It covers every original mature training cohort and application, including unscored applications, the full event-history calendar, original issued controls, retained nuisance/scalar stages, probabilities, primitive scores and support. Its independent optima validate retained coefficients; they never replace them. The sole representation exception is the seven native naive midnight application-state date columns documented in `VERIFICATION_DESIGN.md`: checked lossless ms/us/ns equivalence on temporary comparison views. All other frozen frame, index and numeric checks remain in force.

A zero branch requires a zero coefficient and zero iteration/call counts. Both independent solves must report success. Such diagnostic flexibility cannot waive a coefficient, objective, gradient, status or solver-setting mismatch.

## Publication and failure handling

Before writing a successful proof, the entry repeats code, input, preserved-artifact and four-output hashes, manifest coverage, protocol/manifest byte identities and the complete source closure. After the final closure hash loop it freshly binds the exact old failure/metrics/verification trio and checks absence of failure markers for the original successful wave18/wave19 sources. The new replay's failure marker must also remain absent. The old wave20 failure is required evidence; it is never erased or treated as a successful ancestor.

Successful verification writes only the new `verification.json`, which binds four new output hashes and the retained input hashes separately. The failure guard replaces only the new replay's canonical metrics with three UNEVALUABLE p=1 outcomes, writes new failure/FAILED verification records, appends three verification-failed ledger events and retains unpublished diagnostic or malformed metric bytes where available. Canonical failure accounting precedes optional backups. A verification failure after 140 evaluated ledger entries therefore adds three events; 140 must not be reported as its complete final history. No old wave20 writer or artifact is used as a failure destination.
