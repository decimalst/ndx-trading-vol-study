# Prospective Treasury execution contract

This is an additive implementation specification before empirical market-feature construction, support inspection, model fitting or scoring. The original `treasury_dealer.yaml` remains unchanged, SHA256 `194fd2ef49cfa8db5542f5e672383b5e2d4ec8f8c724b2af8559d51319aef6a8`. No comparison is registered by this document. The previous goal turn made progress by completing the qualified source-ledger audit and saving its checkpoint; the broader predictive objective remains unmet.

The new protocol module authenticates the literal original YAML before accepting any parsed configuration. It adds an exact execution inventory: the admitted ledger, its independent review and preparation checkpoint, the saved synthetic calibration, the previous 144-comparison family, four inherited market snapshots and new output paths. Hash mismatches stop admission. The private source ledger is not parsed into forecasting inputs until both new comparisons and all 144 inherited identities have been durably journaled.

`read_inputs` authenticates every supplied market and ledger byte payload before parsing the ledger or calling the existing bounded market reader. The runner supplies the fixed four-file inventory; the existing reader checks complete date metadata before extracting only numerical rows at or before October 20, 2025. The source ledger is already a qualified saved-source reconstruction, not immutable historical delivery evidence. January 27, 2020 Z52 retains its explicit cached reported-date assumption and unknown quantities. Rejecting that clock assumption leaves the previously documented strict-clock limitation. This qualification accompanies every resulting status.

The join uses the unchanged established market builder, five-session target builder, Treasury context builder and auction feature builder. It preserves the original QQQ index, all missing positions, source-floor masks, event audits and unscored final origins. There is no imputation, extra feature, fitted transform or market-date selection in this wrapper. Eight prewritten generated tests cover literal dealer-pulse values, target endpoints, causal poisoning, missing source sessions, input immutability, exact source keys, hash-before-decode behavior and malformed-ledger failure. They passed on the first implementation. Five separately prewritten protocol tests bind source ceilings, sample floors, family counts and the exact pipeline projection.

The support audit runs before fitting. Training floors apply to every scheduled first common-feature-complete monthly query, with labels mature by the previous full reference session. Phase, slice and offset counts apply to the common scored-eligible cohort. Actual event identities count separately, simultaneous activations count once, and true-zero or cancelling surprises remain activation dates. The independent verifier reconstructs features and support from the source inputs even when the support gate fails. A reproduced failure remains an unevaluable registered experiment and never triggers a changed floor or a partial model run.

For uncertainty, each phase endpoint uses every original reference-calendar position **within the literal declared phase**, including missing dates, nonauction dates and phase-end immature origins. It does not pad with out-of-phase years or compress to scored/active dates. Modulo-five diagnostics always use global original-calendar positions. The prospectively fixed seed is base + phase_code*10000 + endpoint_code*1000000, with development0/evaluation1 and daily0/active1; the unchanged core adds block length internally. Both comparisons use the same draws for corresponding endpoints. These details resolve caller behavior not specified by the date-free inference primitive; they were fixed before empirical access.

Independent comparisons use coefficient absolute/relative tolerances 1e-7, forecast absolute1e-12/relative1e-7, source-feature absolute1e-12/relative1e-9, and score absolute1e-10/relative1e-8. Probabilities, identities, counts and masks are exact. The verifiers may reuse named prior independent market oracles, but never call the Treasury producer to reconstruct its own forecast or score. No tolerance is increased after observing historical discrepancies.

The runner requires a final independent execution review, authenticates inherited/source pins, runs every selected repository test and freezes current code, sources, protocols, prefit records and prior reports before registration. Six existing tests that replay the later historical period are explicitly quarantined before this run, as explained in [the access correction](HISTORICAL_TEST_ACCESS_CORRECTION.md). All selected and quarantined test IDs are saved before execution. This is not an unqualified full-suite pass, and the later historically evaluated period cannot be called untouched. Successful generated calibration is reused at its original pinned settings and is not rerun or tuned. Existing attempts, outputs and check logs are never silently overwritten or restarted. Tests for durable registration and retained failures are adapted from the prior study, with the new 144+2 family; an additional generated integration test verifies that the actual runner registers before input decoding and stops before fitting/scoring on independently confirmed insufficient support.

Review additionally exposed a late-publication failure path in the initial unfrozen wrapper. Prewritten regressions now require a failed final hash check or journal write to invalidate both registered comparisons at p=1. Any provisional metrics are renamed to an explicit attempted artifact, and the ledger appends invalidation entries; evidence is retained, not overwritten or rerun. A terminal-publication failure uses the same mechanism. Both completed and failed metrics/terminals carry the Z52 clock qualification and historical-period access correction. The freeze verifier rejects an empty or incomplete current code inventory, missing admitted inputs, and absent or inconsistent selected-test evidence. The generated late-failure and empty-freeze regression failures are preserved alongside subsequent passing results.

The saved execution has separate input/support, forecast and score verification reports. It publishes a completed result only if the corresponding checks and frozen artifact hashes agree. Any registered source/support/arithmetic/fit/verification exception retains both contrasts at p=1 and no lead. All past failures remain in the cumulative family. The source preparation, generated tests, selected-suite pass and nominal uncertainty intervals do not themselves establish a predictive signal or untouched-future confirmation.
