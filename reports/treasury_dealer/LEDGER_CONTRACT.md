# Prospective Treasury source-ledger assembler

Pure input assembly, specified before implementation and historical application. The caller authenticates raw, report and private-payload hashes against the completed source audits before calling this module. This function does not fetch, open, repair or independently authenticate sources; its return is not an independent certificate or predictive admission.

API build_ledger(identity_rows, accounting_rows, accounting_payloads, recovered_rows, clock_reviews) returns exactly events and evidence lists. Both row lists are nonempty, already sorted and unique by (auction_date,cusip), and have exactly matching ordered membership. Dates are literal ISO within 2010-01-01..2025-10-20, announcement no later than auction, CUSIP exactly nine uppercase alphanumeric characters containing a digit. Event IDs are auction_date_CUSIP. Whole original private accounting payloads and whole new recovered payloads are supplied as event-ID-keyed dictionaries. There is no hidden extra event, ignored payload, deduplication or sorting repair. The original payload keyset equals exactly the old completed-accounting keyset. Recovery keys are only old noncomplete, nonexcluded events. A recovery cannot overwrite an old known event, and its original_status and own event identity must match.

A known original requires original identity status PAIRED_METADATA_RECONCILED with nested identity RECONCILED_METADATA_ONLY, accounting status PAIRED_SOURCE_AMOUNTS_AND_OFFERING_MATCH, no unavailable notice, all three stage statuses PARSED, comparison without mismatches, exact same sixteen named finite decimal fields across saved PDF/XML, and VERIFIED_STATED_OFFERING_AGREEMENT with USD units and equal positive integer dollars from announcement PDF, announcement XML and result XML. Source offering units remain USD / USD_BILLIONS / USD_BILLIONS. Monetary result fields remain nonnegative exact integrals; dealer accepted is between zero and positive competitive accepted. Bid-to-cover is positive; high yield is nonnegative. Decimal decoding is exact, with no float conversion or donor-share calculation. Emitted amounts are exact ints; yield and bid-to-cover emit exact fixed-point decimal strings with preserved value and scale.

Recovered values use the new whole saved payload schema (identity, result_xml, result_pdf, offering, original_status, status). Its status is PAIRED_SOURCE_AMOUNTS_AND_OFFERING_MATCH. All old notice associations remain visible in evidence. Recovery closures must cover the exact old notice URL set without duplicates, match prior disposition and final identity/lineage, provide agreeing chronology and source hashes, and use one of the two documented resolved closure statuses. Every formerly unavailable notice must be among those explicitly closed; no assumed disappearance or new unexplained notice.

Known original tenor and reopening come only from identity.final_lineage, with supported original tenor2/3/5/7/10/30 and exact boolean reopening. Availability is identity.identity_available_date, at or after auction/result release; no availability inferred from a current fetch. Unknown rows retain none of the five financial values, none of original tenor/reopening and only the exact caller-supplied reviewed availability_after_date and/or clock_upper_bound_date. clock_reviews keys must equal the final unknown ID set, each with exactly those two clock keys plus nonempty evidence_class and nonempty source_evidence dict. Reviewed unbounded clocks (both None) remain explicit. Non-null clocks are within the source envelope and cannot precede auction; a bound cannot precede an exact clock. The supplied evidence, not this code, distinguishes exact documentary clock from a qualified archival upper bound.

EXCLUDED_DOCUMENTED_CONTINGENCY_TEST produces EXCLUDED only with its explicit exclusion notice disposition retained, no financials/tenor/reopening or invented clock. The original accounting disposition remains in evidence. Other unrecognized status combinations fail rather than becoming zeros or exclusions.

Every event has precisely the eleven fields consumed by treasury_dealer_features plus clock_upper_bound_date (None for known/excluded). No financial feature, log amount, fraction, donor selection or history is computed. Evidence separately preserves original statuses, recovery flag, final disposition, all old notice associations, identity provenance, recovered source/closure provenance and reviewed clocks. Inputs are never mutated.

Ten prewritten generated tests cover literal values/field schema, additive recovery, strict full membership/order, prohibition of known overrides, PDF/XML and offering disagreement/nonintegral/nonfinite inputs, explicit zero dealer versus missing event, both reviewed unknown clock forms, missing/extra/invalid clock evidence, notice closure/exclusion defects and exact input preservation. All source fixtures are invented except literal status/field names. No actual historical financial application occurs in the component run.


Prefreeze generated compatibility correction: the frozen source parser accepts an integral plain zero such as 0.0000000, and the existing saved-output writer uses str(Decimal(...)), producing 0E-7. The initial assembler rejected that valid transport. A regression was added to the existing known-mapping method and captured in LEDGER_DECIMAL_SERIALIZATION_RED.log before the source correction. The assembler now accepts serialized zero tokens matching 0E-[0-9]+ in addition to plain nonnegative decimals. Nonzero scientific notation remains unsupported. Yield/BCR output uses exact Decimal fixed-point formatting so the downstream feature decoder receives its declared plain decimal shape. Original payloads and source tokens are not rewritten. No historical payload or source quantities were read to discover or test this correction.
