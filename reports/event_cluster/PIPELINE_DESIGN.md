# Original-cohort event-cluster pipeline

The new [pipeline](/Users/byrons/code/trading-vol/ndx-vol-experiment/src/event_cluster_pipeline.py) operates only on supplied tables. It performs no file loading, source acquisition or original-model fitting. Actual historical source admission and empirical execution have not occurred. The successful tests described here use generated temporary data, not market observations.

## Interface and outputs

`forecast_panel(features, targets, upstream_panel, upstream_fits, upstream_states, original_index_config)` returns `(panel, newfits, newstates, memory, support)`. The final argument is the unchanged wave18 index configuration, including its original model list and feature geometry. It is not the new four-model configuration. The caller must first obtain the exact original records through the separate immutable-admission layer.

`MODELS` is `('baseline', 'recent_frequency', 'nuisance', 'cluster')`. `PANEL_COLUMNS` is the frozen `range_alert_models.PANEL_COLUMNS` tuple: origin, model, horizon, feature cutoff, target end, availability date, binary target, probability, Brier loss, fit origin, fit cutoff, training count, last training target, last training availability and phase, using the exact original column spellings/order. The original baseline and recent-frequency rows are copied without changing values. New model rows inherit their matching original baseline metadata and labels, replacing only model, probability and loss. Every scored origin must have exactly four rows.

Every `newfits` record retains the original `fit_origin`, `fit_cutoff_date`, `train_n`, `train_first_origin`, `train_last_origin`, `train_last_target`, `train_last_available` and `application_n`. It adds `source_fit_origin`, preserves the full ordered `application_origins`, saves all four `application_probabilities` arrays, and stores the new staged `model_audit`. An original baseline fit is a frozen offset source, not a new monthly fit. Each retained original monthly application group produces one new nuisance fit and one scalar cluster stage, even if the group has no scored labels.

`STATE_COLUMNS` starts with `origin`, `feature_cutoff_date`, `source_fit_origin`, `baseline_logit`, `baseline_probability`, `recent_frequency`, `nuisance_probability`, `cluster_probability`, and `scored`. It then includes every `event_cluster_features.MEMORY_COLUMNS` column except the duplicated feature cutoff. Thus each original application retains both new probabilities, its original issued offset and controls, all six fitted history coordinates, the diagnostic excess adjacency, integer summary audits, and the four structural history-window dates. State origin/cutoff/fit dates are pandas timestamps; fit JSON dates retain the original ISO date strings.

`memory` preserves the entire original reference index and the exact feature-module column order, including unknown warmup rows. Its fitted candidate is raw `adjacency_fraction22=C/21`. The excess-adjacency coordinate is a diagnostic only and does not enter the six fitted history features. `support` contains status `COMPLETE_ORIGINAL_COHORT_WITH_EVENT_HISTORY`, the unchanged common application/scored/monthly counts, `history_columns`, complete `original_support`, per-fit original cohort metadata plus `source_fit_origin`, `training_history_rows` and `application_history_rows`, and `unknown_history_policy='whole_trial_failure_no_row_mask'`.

## Complete preflight before any new fit

The pipeline first calls frozen `issued_calibration_models.replay_issued`. This checks the original full application schedule, all old fit/support/transform records, original baseline logits and saved probabilities, phase/maturity fences and the full-calendar recent-frequency state. It does not invoke an old optimizer. Labels may be inspected for these support and identity checks; they do not select the monthly application schedule or enter a query's fit.

The feature module then constructs mature-label history on the full target calendar. Its index and preceding-session cutoff must match the original feature table exactly. For every original monthly fit, the pipeline calls frozen `range_alert_models.training_mask` with the original features, targets, fit origin and minimum training count. Every one of these original training rows and every original application must have all six finite history features. A gap anywhere, including a later unscored application, aborts the entire trial before the first new `fit_stages` call. The new history never creates a smaller complete-case cohort, a new calendar or a substitute fit origin.

The same complete pass validates each new bounded transformation and computes historical offsets by applying `event_cluster_models.baseline_logits` to the original monthly training rows using that month's saved baseline audit. These are explicitly current-month in-sample baseline offsets, not previously issued historical probabilities. Application offsets and baseline probabilities come from the original issued replay; neither an inverse logit nor a later baseline fit is used. Original cohort metadata are checked for exact equality.

Only after every fold passes does the pipeline call `fit_stages(train_history, aligned_y, application_history, train_eta, application_eta, saved_baseline_probability)`. No future application labels are passed into this function. Both returned probability arrays must be valid for every application before any scored-row selection. The new model's numerical solver and coefficient audits are specified separately in its owned model design.

All original applications and fits are saved first. Scored new rows are then selected using the already verified original baseline panel. This preserves the original development maturity fence and any final unscored application. `validate_panel` checks the complete four-model panel and, separately for nuisance and cluster, maps that arm to the frozen original candidate label and invokes the original three-model validator with both unchanged controls. Final counts must match the complete original support record.

## Tests written before implementation

The ten [pipeline tests](/Users/byrons/code/trading-vol/ndx-vol-experiment/tests/test_event_cluster_pipeline.py) were written before the producer module existed. [pipeline_initial_red.txt](/Users/byrons/code/trading-vol/ndx-vol-experiment/reports/event_cluster/pipeline_initial_red.txt) records the expected missing-module failure. The first implementation passed all **10 tests in 35.149 seconds**, recorded in [pipeline_implementation_checks.txt](/Users/byrons/code/trading-vol/ndx-vol-experiment/reports/event_cluster/pipeline_implementation_checks.txt); scoped Ruff checks also pass.

The generated fixture marks the first 23 original feature rows incomplete before creating its synthetic old fits. This supplies the causal history warmup without changing a saved old cohort. A separate fixture deliberately omits that warmup and confirms that the new pipeline fails, rather than deleting old training rows. Other tests cover exact four-model schema and bit-for-bit original controls; unknown history in an old training row or final application preventing all new fit calls; an unchanged input archive and forbidden original optimizer calls; exact current-month training-offset replay and mature labels; future-label mutations leaving earlier memory and states unchanged; retained final and phase-boundary unscored applications; rejection of a nonfinite probability at an unscored application; and complete panel validation for both new arms.

These checks establish synthetic orchestration and causal invariants. They are not an empirical support count, an admission of actual source tables, a predictive result, or a substitute for independent reconstruction of the complete new experiment.
