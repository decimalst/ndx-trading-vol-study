# Precision gate score and independent reconstruction contract

This component uses generated inputs only before empirical registration. Existing frozen sources, previous comparisons and result artifacts remain unchanged. The root runner authenticates the entire fixed precision_gate.yaml; both new score modules additionally enforce the exact scientific date, support, inference, model-history and family fields before computing uncertainty. Extra descriptive protocol fields do not relax those checks.

The producer API is evaluate(panel,calendar,prior,protocol). The independent API is verify_scores(panel,calendar,metrics,prior,protocol). Family helpers _prior(default146), _probabilities, inherit_family(previous,signature) and failure_metrics(error,signature,prior=None) are exposed for the runner. Inheritance preserves all144 older rows and the two exact Treasury rows, appending their source path, SHA256 and row index. Both structurally valid COMPLETED and UNEVALUABLE prior terminal records are supported; unevaluable rows require all three probabilities to equal1. The real previous source/status is authenticated by the runner. Three new failed comparisons retain p1 and terminal UNEVALUABLE; a two-argument failure helper requires the runner to attach the authenticated inherited family before publication.

The scored panel has four arms base/adaptive/constant/contextual on exactly the same origins, targets and metadata. Required columns are origin,model,prediction,y,loss,target_end,phase,offset,fit_origin,training_cutoff,train_n,gate_n,gate_status,state. Numeric forecasts/targets are positive and finite, state is finite, counts/offsets are literal integers, train_n>=1000, gate_n is0..1260, and gate_status is fitted exactly when gate_n>=252, otherwise cold_start. Dates are native naive midnight timestamps. Target endpoint is the fifth following original calendar session; offsets are original global positions modulo5. The monthly fit is nonfuture and in the query's month; its training cutoff is the preceding full-calendar session. All complete scores stay within development2016-01-01..2019-12-31 or evaluation2020-01-01..2025-10-20, with target maturity bounded by the applicable phase endpoint. QLIKE is recomputed from y/prediction. The producer requires exact stored QLIKE equality; the independent path reconstructs the losses and compares saved numerical losses at absolute1e-10/relative1e-8 tolerance.

Scorer checks concern the supplied paired issued-forecast ledger. Independent forecasting verification owns reconstructing actual monthly first-feature-complete scheduling, mature issued-history membership, fitted parameters and cold-start coefficients/predictions from source inputs. Status/count agreement alone does not establish those upstream identities. Cold-start rows remain in every daily comparison and diagnostic; they are not discarded or assigned missing/zero loss.

Support is checked for both phases and both evaluation slices before any bootstrap call. Every phase requires505 common scored origins and252 origins whose gate_status is fitted; each fixed evaluation slice requires252 common origins and126 fitted origins. Each of the five global offsets in each phase requires63 common scored origins. There is no fitted-gate floor per offset beyond the prescribed phase/slice floors. Cold-start and fitted counts are separately reported and sum to the common total. Failure of any support requirement aborts the whole attempt.

The sole endpoint is the daily mean contextual-minus-control QLIKE difference, separately against base, adaptive and constant. Its time domain is every original reference-calendar position within the literal phase, including missing-feature/target and immature phase-end positions. Paired observed differences are reindexed into that uncompressed calendar; unselected positions remain NaN, and their selection mask is false. No out-of-phase years are padded into an endpoint. Producer inference reuses frozen treasury_dealer_inference.masked_mean_inference: circular masked ratios of sums at blocks21/63/126 with399999 draws and full-calendar influence HAC126. Seeds are20261003+phase_code*10000, with development0/evaluation1 and the frozen primitive adding block length. All three contrasts share draws within a phase. Any zero-support replicate fails rather than being removed or redrawn.

Each comparison uses the maximum two-sided probability over both phases and all three blocks/HAC. It must satisfy Holm3<=.05/(26*27), cumulativeHolm149<=.05 after all146 inherited probabilities, phase mean differences<=-.005 in both phases, and strictly negative differences in every phase offset and each of the two evaluation slices. The exact float64 wave threshold is Python .05/(26*27), as fixed before registration. Annual differences are descriptive. All three comparisons must qualify before the single precision_gate lead is emitted.

The result top keys are status,rows,inherited_rows,leads,hypothesis_count3,cumulative_hypothesis_count149,common_scored_origins,fitted_gate_scored_origins,evidence_class,evidence_limitation. Rows are ordered base/adaptive/constant and contain study precision_gate,candidate contextual,control,horizon5,score qlike,phases,p_conservative,p_holm_wave,p_holm_cumulative,verdict. Each phase is a flat single-endpoint record with name,mean,n,full_calendar_n,hac,block_inference,p_conservative,fitted_gate_n,cold_start_n,candidate_loss,control_loss,first_origin,last_origin,ci95_envelope,annual,offsets,stability. Diagnostics contain n,mean,fitted_gate_n,cold_start_n plus their offset, literal slice bounds, or year/calendar_origins/missing_origins. Unsupported annual means are None; required groups always have positive support.

Both completed and failed producer metrics include the exact EVIDENCE_CLASS/EVIDENCE_LIMITATION constants from the new metadata-only precision_gate_protocol module. The independent checker requires those same complete exact fields and rejects Treasury source-clock qualification fields as extraneous. The qualifications disclose reused development/evaluation windows, earlier regression access to the period beginning2025-11-03, current-vintage limitations, and this experiment's numerical ceiling2025-10-20. They do not imply that this experiment uses Treasury data.

The independent score module never imports precision_gate_score, its diagnostics, or the producer bootstrap. It separately reconstructs pairing, QLIKE, gate-status/support counts, phase/mask assembly, diagnostics and pass decisions. Shared frozen independent utilities are verify_claims_release_scores._calendar/_dates/_holm/_integer/_real/_compare and verify_treasury_dealer_scores._indexed_inference. The latter uses explicit circular-index block tables instead of the producer's cumulative-prefix sums and independently assembled lag products/HAC; it was already tested against literal indexed and serial fixtures. Probabilities, counts, dates, schema and inherited rows compare exactly; remaining reported numerics use absolute1e-10/relative1e-8. This is computational independence, not separate human authorship. Successful proof reports3 comparisons,6 phase endpoints,18 bootstrap runs,6 HAC runs and146 inherited comparisons verified.

The predeclared existing daily-mask synthetic calibration for the identical inference core is reused as specified by the root protocol. It is a diagnostic of the prescribed generated process, not exact market coverage or adjusted-tail calibration; this component neither reads actual market scores nor reruns calibration. Generated integration tests privately mock draw count31 while the public protocol remains fixed at399999.

Prewritten evidence is retained in SCORE_RED.log and SCORE_VERIFICATION_RED.log, both genuine missing-module failures before implementation. Producer tests cover paired arms, inherited failures, global calendar gaps/tails/shared RNG, cold-start inclusion, exact fitted-support boundaries, daily/slice/offset support before inference, chronology/count/type/loss corruption, inclusive probability/effect boundaries and control vetoes. Independent tests reconstruct all outputs and corrupt every inference/family/qualification/diagnostic group. SCORE_FIRST_IMPLEMENTATION.log preserves the original invented fixture failure: a five-date cold-start cadence created an offset with no contextual improvement, correctly failing the negative-offset gate; changing the invented cadence to seven exercises both statuses in every offset. SCORE_VERIFICATION_FIRST_IMPLEMENTATION.log preserves an immutable-tuple assignment error in a corruption fixture; only that fixture container was changed to a list. Neither correction changes scientific constants or source calculations. Final generated tests and scoped lint are retained in SCORE_GREEN.log and SCORE_VERIFICATION_GREEN.log.
