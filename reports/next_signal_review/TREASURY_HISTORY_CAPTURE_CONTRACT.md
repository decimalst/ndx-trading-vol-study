# Treasury full-history document capture contract

This is a prospective source capture step. It adds zero predictive comparisons, admits no financial values and makes no first-vintage or intraday publication claim. The completed notice audit leaves identity substitutions, rescheduling, corrections, a contingency test and one unavailable notice for separate reconciliation. This capture preserves those events and never retries special notices.

`build_history_selection(root: Path, source_pins: dict[str,str]) -> dict` is read-only. It first authenticates all supplied pins, requiring the 16 projected annual `inventory_capture_v2/{2010..2025}/metadata.json` files, `TREASURY_INVENTORY_CAPTURE.json`, `TREASURY_DOCUMENT_CAPTURE.json`, and `TREASURY_FULL_NOTICE_TERMINAL_AUDIT.json`. It validates the entire metadata inventory and all six original URL roles with the frozen document guards before filtering literal Note/Bond types and the 2/3/5/7/10/30-Year term buckets. Remaining term is preserved independently of the term bucket. No financial fields are accepted in projected records.

The frozen inventory amendment permits an exact empty `term_bucket` only. The field remains empty, with no inferred tenor, and does not match the six selected coupon buckets. Missing, null, numeric and whitespace-only buckets remain invalid; every other core field must be a nonblank string. This follows the field-level semantics of the frozen inventory projector. Root's independent metadata check reports that all 573 such rows in the actual inventory are CMBs.

The deterministic selection has `records`, retaining each full original record, metadata path/row and explicit requested roles; `requests`, the URL-sorted deduplicated transfer plan; `missing_requested_roles`, an explicit gap list; and `counts`, including all original and requested role associations. Only announcement PDF/XML and competitive-result PDF/XML roles are requested. Missing filenames are never invented. Every request retains minimal role memberships and full six-field metadata memberships with the additional role name. All other role associations remain in the original records.

`capture_history(root: Path, selection_path: Path, checkpoint_path: Path) -> dict` requires status `READY_FULL_HISTORY_CAPTURE`, all checkpoint pins unchanged, every source pin included, the exact selection pinned, and `expected_counts` exactly equal to all eight selection counts. It reconstructs the selection from pinned projected metadata before output or transport. Root will freeze the production selection, expected 1,138 events and 88 reused original URLs, after inspecting this implementation. Synthetic fixtures use smaller counts; no empirical capture was performed during implementation.

Exact pilot URL matches must reuse their original body and receipt paths without copying or downloading. The checkpoint must pin body, receipt and the receipt's sibling `headers.txt`; their hashes must match the pinned pilot capture. Frozen transport validation is rerun and pilot role memberships must be a nonempty unique subset of expanded history memberships. Failed or conflicting pilot provenance stops before any output or request.

Fixed output paths are private `data/source_discovery/treasury_auction/history_capture_v1` and public `reports/next_signal_review/TREASURY_HISTORY_CAPTURE.json`. Existing output directories or reports prohibit replay. A durable private `started.json` binds the request list before transport. Certificate-verified curl uses three workers, HTTPS only, no redirects/retries, a 45-second transfer timeout, 50-second subprocess timeout and existing 8 MiB PDF / 2 MiB XML limits. New private directories/files use modes 0700/0600. Each attempt retains body, headers, complete transport receipt, stderr and summary. Individual HTTP/timeout failures remain explicit while other requests finish. Final pin drift is retained in the terminal report and prevents a successful status.

The script `scripts/capture_treasury_history.py` only consumes the prepared selection/checkpoint; it does not create either or authorize a new capture. Familiar output fields include URL, format, memberships, body/receipt paths and hashes, headers hash, status and source capture mode. `VERIFIED_TRANSPORT_SCHEMA_ONLY` is the established transport label; this stage performs no XML/PDF extraction or financial decoding.

Ten generated contracts were written before implementation. The genuine missing-module failure is saved in `TREASURY_HISTORY_CAPTURE_RED.log`. They cover deterministic complete selection, gaps, all-year pins, prefilter date/URL checks, reuse with expanded associations, checkpoint/count/tamper failures, receipt identity, private files, bounded transport failures, replay refusal, three-worker configuration and final pin drift.

All ten passed on the first implementation (0.345 seconds). The final run after formatting also passed all ten (0.327 seconds), saved in `TREASURY_HISTORY_CAPTURE_GREEN.log`; scoped Ruff checks and formatting passed. Tests used temporary generated sources and mocked curl only. No real selection was built or real capture invoked by the implementing agent.

Root's prefreeze review then found that the new selection guard had incorrectly rejected the inventory's preserved empty CMB bucket. Two new generated contracts were written and run before correction: `TREASURY_HISTORY_CMB_REGRESSION_RED.log` records the valid CMB rejection and the incorrect acceptance of a whitespace-only bucket. The guard was then aligned with the frozen inventory's exact-empty field semantics. This changes no frozen helper or source record and assigns no tenor. The earlier ten-test GREEN remains evidence for the earlier implementation; all twelve corrected contracts passed in 0.380 seconds in `TREASURY_HISTORY_CMB_REGRESSION_GREEN.log`, with scoped Ruff and formatting clean.
