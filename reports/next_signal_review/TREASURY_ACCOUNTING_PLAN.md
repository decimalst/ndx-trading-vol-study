## Before source amounts

Pin the capture, fixed selection, PDF text, earlier identity checkpoint, source code/tests and documentary reports before applying new parsers. Verify every pin before reading source values. Require selected event dates, exact result CUSIP and a dated competitive-result release header within 2010-01-01 through 2025-10-20. XML ReleaseTime alone is not a release date. Verify the announcement identity and classify every known special notice associated with each pilot event before amount conversion.

Determine original tenor from the source's stated dated date and maturity date: their month/day must agree and their exact year difference must be one of 2, 3, 5, 7, 10 or 30. Require agreement of these dates in the competitive PDF and XML. Reopened securities also require matching original dated date and original issue date in the two representations; original issue precedes the reopening issue. New issues require an explicit non-reopening flag and a matching whole-year stated term. A settlement date moved to a working day does not replace the dated date. No rounding of remaining life is permitted. This is documented security lineage from the captured source; it is not independent evidence of historical delivery or an exhaustive security master.

The metadata-only lineage tests cover a true original-five-year reopening offered with two-year remaining term. One synthetic malformed-container case initially performed a no-op because its fixture used a self-closing results element; before any source application that fixture mutation was corrected and checked to differ from the original. ## Source quantities and independent checks

The XML parser returns precisely 14 integral par-dollar amounts and the published bid-to-cover and high-yield values. High yield stays in percentage points. Missing, blank, duplicate, nested, namespaced alias, nonfinite, signed, exponent or improperly fractional amounts fail. Actual zero is retained.

Own-account primary/direct plus customer/indirect accepted amounts must equal competitive accepted, with the corresponding tendered identity and accepted no greater than tendered in each category. Total accepted/tendered include public noncompetitive and FIMA plus SOMA. Bid-to-cover uses public totals excluding SOMA; its printed two-decimal value must be within 0.005 of the exact ratio, using integer cross products. Do not derive bid-to-cover from offering size or the competitive-only denominator.

A separately authored PDF parser maps labeled Tendered/Accepted rows, public subtotal, bid-to-cover footnote and percentage-suffixed High Yield. It does not import XML amount code or constants. Each parser must pass prewritten generated tests before real-data application. Require exact equality of the 16 named values between formats; record every mismatch and extraction failure. The rounded bid-to-cover accounting tolerance does not weaken exact comparison of the published PDF/XML ratio. Current paired agreement alone does not prove first-vintage availability.

Keep numerical outputs private under the already ignored source-discovery directory. The public audit may contain counts, exact evidence hashes, event identities, classifications and names of conflicting fields, but no model forecasts or acceptance verdict. Preserve per-format parse results even if the other format fails, so an accounting failure cannot be mislabeled as a predictive null.
