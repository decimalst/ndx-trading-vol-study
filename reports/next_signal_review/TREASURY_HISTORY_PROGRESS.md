# Treasury auction history: capture and initial reconciliation

The complete selected auction history has been captured and inspected. Offering-size reconciliation now succeeds on all 20 previously reconciled pilot events, with an independent saved-output audit. The initial full-history identity pass reconciles 835 auctions and retains 302 source cases for explicit follow-up; one documented contingency test remains excluded. No Treasury forecast, feature panel or score has been produced, and the registered comparison count remains 144.

These are **first-failure counts**, not an exhaustive list of every condition each event must pass. For example, one substitution also has a February month-end boundary, and two CUSIP-layout cases have additional visible month-end boundaries. A formatting fix does not establish that the subsequent checks pass. None of the 18 actual substitutions has passed this first identity helper yet.

The three bounded exception reviews are complete. All 252 term-label cases agree across the announcement, result and paired XML metadata; one extracted `Mont h` spelling was checked against the complete original page, which prints `Month`. The 39 initial lineage failures contain 22 February month-end cases and 18 confirmed substitutions, with one overlap; the reviewed source labels agree without changing any date.

Seven complete announcement pages establish four genuine amendments and four independent column-order extraction failures, with one event in both groups. Existing reviewed notices explain the scheduling changes, including the same-date June 2017 amendment to auction closing times. These findings specify the next parser changes; they do not replace an implemented and tested reconciliation pass.

The December 24, 2019 event whose special notice original is unavailable passes the paired announcement/result identity checks, but its missing-notice limitation remains attached. It is not silently admitted by that narrower success.

The next implementation should add separately tested handling of the observed offering labels, amended announcements, column layouts, February month ends and original-versus-current dates. Then rerun the complete source reconciliation under a new checkpoint, preserving this initial pass. Complete full-history bidder amounts and offering controls before freezing and running the prospective predictive experiment.

## Preserved implementation failures and limits

The first capture launch correctly stopped before any request because the root checkpoint omitted 88 existing receipts and 88 headers. A new checkpoint added the independently verified files; the original checkpoint and failure record remain intact. A metadata-selection regression involving the previously permitted empty cash-management-bill term bucket was caught and fixed with a failing test before capture.

The first offering parser rejected 19 valid own-security identities because it also counted a supplemental CUSIP label. Its failure report and single successful amount remain unchanged; a separately tested label adapter reconciled all 20 pairs. An initial launch without the repository import path stopped before source application and was rerun with the correct environment.

Independent wrapper review found missing required-input and exact-inventory checks before full metadata application. The original pinned, unapplied wrapper was retained and a separate bound wrapper was used after generated binding tests passed. A later root identity-wrapper variable-name error stopped before its first reconciliation; a new wrapper corrected only that runtime name, preserving the original code and failure checkpoint. The completed identity pass uses the corrected wrapper and verifies source pins at both boundaries.

Current-source hashes establish reproducibility of this capture, not historical cryptographic delivery. Dated primary content, paired representations and reviewed known notices support qualified exploratory research with those limitations stated. Missing documents and unresolved identities remain distinct from predictive failures. Protected later market arrays and all previously frozen model results remain unchanged; this source work makes no signal-qualification or trading-profit claim.
