# Index-return and calendar timing novelty review

**Finding: no source-ready, economically distinct civil-calendar gap was identified.** Weekday, beginning-of-month, month/year/quarter-end, scheduled macro timing, elapsed duration, and overnight/daytime information are already represented. Actual announced index-maintenance events and product-specific expiration schedules were not found as explicit forecasting inputs, but neither has an admitted historical point-in-time evidence package in the reviewed designs. They are potential source questions, not permission to manufacture calendar flags or run another historical screen.

This bounded review reads protocols, implementation and design notes only. It does not read raw source arrays, forecast panels, fits, numerical outcomes, new support counts or protected observations; no functions constructing features or forecasts are executed. All existing 394 Python files and completed reports remain unchanged. “Registered/implemented,” “used as a control,” and “separately tested candidate” are distinguished below. This is not a fresh audit of every historical execution certificate or result.

## Two important category distinctions

**Event clustering is endogenous history, not an announcement calendar.** Wave20 takes the last22 mature binary SPX risk-alert labels, conditions on count, latest label, expected adjacency and linear recency, and adds the observed adjacent-pair fraction. Wave21 rechecks the same retained output with a declared date-representation change. Neither adds CPI dates, expirations or a new external event schedule. Calling an upcoming announcement “event clustering” would conflate two different inputs; merely changing the binary-history window would repeat the tested history mechanism. [Wave20 definition](/Users/byrons/code/trading-vol/ndx-vol-experiment/reports/event_cluster/DESIGN.md:13), [wave21 scope](/Users/byrons/code/trading-vol/ndx-vol-experiment/reports/event_cluster_replay/DESIGN.md:5).

**Expiration composition is already registered, while an expiry-day rule is not.** The free option-flow study defines the actual contract-volume share with days-to-expiration at most7, inside a fixed four-component composite. Its implementation computes DTE from each recorded contract expiration. This is not an independently isolated expiration effect, and registration/implementation do not establish evaluable historical support. No explicit exchange-specific OPEX/third-Friday/VIX-settlement forecasting indicator was found in the scoped Python/protocol/design search. The existing calendar audit expressly left such a source unadmitted. [Registered composite](/Users/byrons/code/trading-vol/ndx-vol-experiment/free_signal_study.yaml:61), [DTE and share](/Users/byrons/code/trading-vol/ndx-vol-experiment/src/free_signal_study.py:244), [prior source caveat](/Users/byrons/code/trading-vol/ndx-vol-experiment/reports/sign_memory/NEXT_CALENDAR_AUDIT.md).

Existing daily OHLC cannot supply that boundary observation, and the NQ study's first/middle/last-hour RV shares are another defined measurement, not a substitute SPX cutoff source. ## Recommendation

Do not register another date-only screen on this novelty review. The previously identified civil-quarter gap has already been implemented; replaying its prospectus as a new opportunity would be stale. There is no basis here for calling weekday, month-end, pre-FOMC, overnight/daytime, or a shifted endpoint window an orthogonal new mechanism.

If the broader source search selects index maintenance, the potentially distinct input would be **an original, advance-published index membership or weight-change notice with its stated effective date and announced content**, not a civil quarter-end proxy. No such forecasting implementation or admitted notice corpus was found. Its conjectured mechanism would be adjustment associated with an announced benchmark change; this review supplies no evidence for predictability or realized trading flows. Before consideration, authenticate the exact benchmark/product, original announcement time, effective-time rule, revisions/cancellations, historical rule changes and exceptions, and enough pre-origin documentary history. The same source-first requirement applies to product-specific expirations. Current calendars, “third Friday” arithmetic, quarterly holdings filing dates, or future realized sessions do not meet that condition.

This is a **no-ready-novel-gap finding within the inspected timing families**, not proof that every possible calendar effect has been tested or rejected. Continue the broader search for a distinct admitted information source; make no new cohort or model from this note.
