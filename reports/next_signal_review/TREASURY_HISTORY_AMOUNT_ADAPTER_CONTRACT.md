# History result amount adapter

`parse_history_result_amounts(raw, *, auction_date, announcement_date, cusip, announced_cusip)` returns the same 16 named Decimal values as the frozen `treasury_auction_amounts` parser. The 14 par fields remain US dollars; bid-to-cover remains a two-decimal ratio and high yield remains percentage points. No new features, ratios, currency scaling or source-admission decision are added.

The caller must independently reconcile the original announced security and final security before calling. Both supplied CUSIPs are required nonempty exact nine-character uppercase alphanumeric strings. The source `CUSIP` must equal the supplied final `cusip`. Nonempty source `AnnouncedCUSIP` must equal the separately supplied `announced_cusip`; absence or empty text is allowed only when the two supplied identities are equal. Thus an actual substitution requires explicit matching source `AnnouncedCUSIP`. An optional nonempty `OriginalCUSIP` must name one of the supplied pair; a different value is not discarded or aliased and fails. All raw XML bytes and fields remain untouched.

The frozen bounded XML identity decoder supplies exact, direct metadata leaves and rejects malformed encoding, entities, duplicate/nested/namespaced identity fields and containers. The new identity check retains selected/source auction and announcement date equality, source scope and chronology. Nominal NOTE/BOND, explicit noninflation status and the inherited floating-rate rule are checked before any Decimal conversion. This function does not weaken the old common-CUSIP checker or infer lineage from amount agreement.

The frozen parser is monolithic, so its amount extraction and accounting are carried into this new module with the original constants and exact formulas. Every required numeric field remains one direct unaliased results leaf, and the new adapter explicitly rejects attributes on these numeric leaves. Required tokens retain original precision/nonfinite/unsigned/integral restrictions. Category sums, acceptance ceilings, noncompetitive/FIMA/SOMA totals, positive public and competitive acceptance, and the inclusive exact half-cent public bid-to-cover cross-product test remain unchanged. Integer accounting remains independent of Decimal context precision.

Twelve prewritten synthetic test methods cover an actual final/announced substitution, regular identities and optional fields, contradictions before decoding, `OriginalCUSIP` preservation, dates and class controls, all 16 field structures including attributes, malformed financial tokens, inherited accounting sums/ceilings/totals/zeros, public bid-to-cover boundaries, large exact values and raw XML constraints. The old tests' invented fixtures are reused as generated data, never as historical source values. Expected Decimal values are constructed directly from fixture literals. Genuine RED precedes implementation. Root owns later integration, checkpointing and application; this task does not decode any actual historical financial source.

The first implementation run exposed one fixture transport mistake: the test wrapper used `None` as its default and substituted a valid fixture for an explicit malformed `None` input. The wrapper now uses a distinct sentinel; the prewritten rejection expectation is unchanged. The implementation did not change for this correction. The first run is preserved in `TREASURY_HISTORY_AMOUNT_ADAPTER_FIRST_IMPLEMENTATION.log` alongside the original missing-module RED.

Final focused checks passed all 12 tests in 0.031 seconds; scoped Ruff passed. A read-only AST comparison confirmed that the numeric-token precision loop, Decimal conversion and entire accounting tail are identical to the frozen parser. The prior amount parser, XML identity decoder and original test-file checkpoint hashes are unchanged. This verifies preserved implementation arithmetic, not an independent historical financial audit.
