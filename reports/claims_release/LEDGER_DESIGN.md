Original DOL first-report ledger: preimplementation contracts

The disposition in SOURCE_DISPOSITION.md is fixed before implementing this builder. Only generated fixtures are used in the new contract suite. The literal 2017 and 2018 exception values are supplied by that already documented disposition; all other fixture counts are invented. No historical source bodies, market observations, features, fits or scores are loaded.

The pure API is `build_first_report_ledger(reports, alfred_records, start='2009-05-30', end='2025-10-18')`. It returns exactly `status`, `start`, `end`, `rows`, and `counts`. The status is `FIRST_REPORT_LEDGER_BUILT_NOT_INDEPENDENTLY_VERIFIED`; construction does not certify independent verification. Counts use exactly the row statuses `observed`, `unresolved_correction`, and `no_admitted_release`.

Every row has exactly `reference_week`, `release_date`, `first_report_value`, `status`, `source_url`, `release_text_sha256`, and `source_comparison`. The nested comparison has exactly `kind`, `dol_value`, `alfred_value`, `alfred_realtime_start_date`, `alfred_source_line`, `value_agrees`, and `release_date_agrees`. Its kinds are `exact_agreement`, `documented_original_dol_disagreement`, `unresolved_correction`, and `no_admitted_release`. Missing-source comparisons retain the kind with every other field null. The input's displayed DOL release date is kept distinct from ALFRED's comparison date.

The existing pinned report and ALFRED record validators supply exact source-schema, positive-integer, strict-date, dated-URL and digest validation. The new builder additionally requires an explicit matching body release date for every report, including calendar-named URLs. It rejects duplicate reference weeks on each side, duplicate DOL release dates, and every source row outside the requested scope. ALFRED dates may repeat: the delayed March 2018 comparison can share the following week's vintage date. Bounds must be literal Saturdays within the fixed default scope; a smaller contiguous subset is allowed for synthetic testing. No source date may exceed October 20, 2025.

All ordinary weeks require reports on both sides with exact reference-week, count and release-date agreement. The literal reference week March 17, 2018 requires DOL 229000 on March 22 and ALFRED 227000 on March 29; the output keeps 229000 and March 22 while exposing both disagreements. The literal reference week March 18, 2017 requires the documented DOL 261000 on March 23 and ALFRED 258000 on March 23; the output first_report_value is null and its release date remains March 23. Audit-side raw counts never become its model-facing first-report value. Incorrect exception inputs fail rather than broadening the exception.

Only the four literal Saturdays September 27, October 4, October 11 and October 18, 2025 may have no admitted report. Both input sides must be absent for those rows. Their release date, first-report value, source URL and text digest are null. The complete default output is 856 consecutive Saturdays: 851 observed values, one unresolved value, and four absences. Every interior or boundary gap outside these four weeks fails, including a gap omitted on both source sides. The calendar is never compressed. The rejected March 2014 dummy document is not a parsed report and supplies no row or invented release date.

The prewritten synthetic tests cover exact output schemas, the complete default grid and smaller windows, both literal exceptions and wrong values/dates, delayed ALFRED date duplication, ordinary conflicts, all gap locations, missing comparison values, tail-source rejection, out-of-scope rows, duplicate weeks, explicit body identity, alternate authenticated URL forms, malformed inputs, strict clocks, input-order invariance, and no mutation or output aliasing. All production work is limited to the new module. Existing source modules, tests and frozen artifacts remain unchanged.
