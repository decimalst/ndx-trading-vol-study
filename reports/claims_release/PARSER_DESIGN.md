## Confirmed API and byte layout

`src.claims_release_source.parse_export(payload: bytes, request: dict, expected_sha256: str) -> dict` is the agreed pure boundary. `_parse_value(token)` is instrumentable and returns a positive integer or `None` for `.`. The exact ZIP members are `README.txt` and `obs.,_initial_release_only.csv`; the literal CSV header is `period_start_date,ICSA,realtime_start_date`. Only stored/deflated regular members are supported; the entire ZIP is bounded at 2 MiB, the total expansion at 16 MiB, and the entry count at two. No filesystem extraction is permitted.

The request specifies `requested_url=https://alfred.stlouisfed.org/series/downloaddata?seid=ICSA`, `method=POST`, `mode=first_release_only`, `series_id=ICSA`, `units=lin`, `file_type=4`, `file_format=csv`, `observation_start`, `observation_end`, strictly ordered unique `vintage_dates`, and the immutable `source_ceiling=2025-10-20`. The capture's `created_utc` remains a separate timezone-qualified retrieval/request provenance clock. Additional provenance fields are covered by the request hash. They are not silently discarded from identity.

The README contains `Series ID: ICSA`, `Output Format: Observations, Initial Release Only`, a fixed-width metadata table with the six attributes below, and a `Vintage Dates Specified:` section bounded by `----------` lines. Each attribute's real-time span is `2009-05-28` through `Current`. Its vintage list must exactly equal the request, preserving order and rejecting duplicates. A selected revision vintage need not produce a new initial-release row.

The returned status is exactly `STRUCTURALLY_VERIFIED_NOT_RELEASE_RECONCILED`. `records` contain `observation_date`, `alfred_realtime_start_date`, `value`, `status` (`observed` or `missing`) and physical CSV `source_line`, with the header counted as line 1. `excluded_initial_snapshot` contains only the two dates, source line and reason `initial_2009_snapshot`, without a value. `missing_reference_weeks` enumerates absent Saturdays inside the requested observation interval; explicit `.` rows and excluded snapshot dates are not absent records. It does not calculate model support.

The required top-level hashes are `source_sha256`, `readme_sha256`, `data_sha256` and `request_sha256`. The request hash covers UTF-8 bytes of `json.dumps(request, sort_keys=True, separators=(',', ':'), ensure_ascii=True)`. No `model_ready` field is permitted. The generated test file SHA-256 at full RED is `0ba7f577f09acc26a3f7ca8379579f49e97cb28b141e29983b90e144e8e1ca42`; scoped Ruff checks and formatting passed before implementation.

## Source identity and interpretation

The originating series must be ICSA, Initial Claims, U.S. Employment and Training Administration, Unemployment Insurance Weekly Claims Report, levels in Number, seasonally adjusted, weekly ending Saturday. Treat these as required semantic identity, with exact source spellings/layout taken from the confirmed export. Do not accept similarly named unadjusted claims, continued claims, a different transformation, or a revised-history export.

The official [ALFRED download description](https://alfred.stlouisfed.org/help/downloaddata) distinguishes initial-release-only output from vintage and real-time-period output. It says the initial-release date is carried in `realtime_start_date`; its README records series attributes by real-time period. The [ICSA download form](https://alfred.stlouisfed.org/series/downloaddata?seid=ICSA) is the intended product. The API's `output_type=4` must not be assumed to be the identically named field on the HTML form; bind the actual confirmed request fields.

A README may not identify every request option. If it omits the initial-release-only mode, the registered capture manifest must bind the actual request endpoint, method, parameters, observation/vintage ceilings and returned ZIP hash. The parser must not infer first-release status merely because three columns look plausible. A source URL and hash copied into an untrusted sidecar do not independently establish official acquisition: root's registered capture contract and subsequent DOL release reconciliation provide that evidence.

The input boundary is ZIP bytes plus an independently expected content hash and a strict source/capture manifest. A path wrapper may read those bytes once, but the parser must not fetch the network or extract ZIP members to the filesystem. The return boundary is typed source rows plus a structured audit of identity, hashes, clocks, exclusions and missing coverage, under the API above.

## Required validation order

1. Validate manifest schema, registered source identity/request mode and strict date/time syntax. Bind ZIP bytes to the independently expected SHA-256 before opening them. A hash mismatch must prevent decompression and numeric conversion.
2. Enforce the fixed archive limits before reading member bodies: total compressed bytes, exact allowed member set, bounded individual and total uncompressed sizes, bounded member count, supported compression and no encryption. Reject duplicate member names, unsafe or nested paths, unexpected entries, corrupt ZIPs and inconsistent member lengths/CRC. Read bounded member streams in memory; never call extraction methods. Limits were fixed before tests and must not be enlarged after a real export fails.
3. Validate exact README identity, dated attribute spans and the confirmed data header/column count. Metadata date ranges do not permit rows beyond the acquisition ceiling. Contradictory or duplicate identity fields and unexpected export structures fail explicitly rather than being guessed into a supported format.
4. Preflight **all rows' framing, dates and uniqueness before converting any claims token to a number**. Observation week, first-release date and retrieval timestamp are different clocks. Require valid ISO dates, weekly-ending-Saturday observations, release no earlier than its observation period, and a timezone-qualified retrieval timestamp no earlier than the retained release dates. A modern retrieval date is allowed; it never becomes a historical release date.
5. Reject the whole artifact if any observation date or first-release date exceeds **2025-10-20**. Do this before numeric conversion anywhere in the artifact, including earlier otherwise valid rows. Do not trim the offending row and continue. A numeric-converter sentinel in generated tests must prove zero conversions for a late ceiling violation.
6. Classify the initial **2009-05-28** archive snapshot and older history on clocks before numeric conversion. Root confirmed exclusion of the entire initial snapshot, including old observations backfilled at that snapshot. Pre-boundary first-release rows cannot be admitted; their precise error/exclusion treatment remains part of the schema/API confirmation. The audit retains line identity, dates and exclusion reason without the discarded claims value. A weeks-old observation appearing in the initial snapshot must never be relabeled as newly released on that date.
7. Convert only eligible, fully preflighted numeric tokens. Preserve source units. Reject blank, malformed, nonfinite, zero or negative tokens. Root confirmed that the documented missing sentinel `.` is preserved as an explicitly unavailable row rather than imputed, erased, or converted to zero. Preserve gaps between reference weeks in the audit rather than fabricate rows or silently stitch a four-week window across a gap.
8. Return rows deterministically in declared order with exact provenance and audit accounting. If any required validation fails, return no partially admitted numeric panel. Structural parsing alone must not label a source independently reconciled or forecast-ready.

Here, “before numeric conversion” is precise: decompression and textual framing necessarily read source bytes, but dates, ceilings and exclusions must gate conversion of a claims token into a numeric object. Generated out-of-ceiling tokens must never be passed to that converter or included in failure messages. No real post-cutoff observation is needed to test this property.

## Generated fixture matrix

Fixtures reproduce the confirmed official export structure directly, using small invented weekly values. They are not built by the production serializer/parser, do not import historical datasets, and do not derive expected outputs from production parsing helpers. Most cases share a valid ZIP-building fixture, while the expected typed records and accounting are stated independently. The matrix below records the prospective contracts; the executable 25-method file is the authoritative current case inventory.

| Contract | Meaningful generated check |
| --- | --- |
| Valid initial-release export | A minimal genuine-layout ZIP yields the exact invented eligible dates/values, source identity, member/ZIP hashes and audit counts. Include two ordinary successive releases and a holiday-shifted release; do not require Thursday universally. |
| Series identity | Parameterized changes to series code, source, release, units, seasonal method, weekly convention or levels transformation each fail, even if the data header still says ICSA. |
| Export mode | A forged revised-history/vintage-mode request fails. A plausible first-release-shaped header cannot override a contradictory registered request. Missing required mode evidence fails. |
| Header and metadata structure | Wrong, reordered if unsupported, missing, duplicate or extra fields fail according to the confirmed literal schema. README attribute ambiguity must not be resolved by taking the first/last convenient value. |
| Hash binding | Mutate either ZIP bytes, a member body, a registered hash or source identity. The inconsistent capture is rejected before rows convert. A self-consistent but differently identified source must not pass an independently fixed pin. |
| Archive bounds | Exercise the exact limit and one byte/entry above it; reject duplicate, unknown, nested/traversal, encrypted or unsupported members. Ensure oversized declared members are rejected before decompression. No extraction method may be called. |
| Archive corruption | Truncated ZIP, invalid member content and a bad CRC fail explicitly, without a partial row panel. |
| Three clocks | An old week, its later first release and a modern UTC retrieval remain distinct. Reject malformed/ambiguous timestamps, release before observation and retrieval before release. Preserve an accepted non-Thursday release. |
| Source ceiling | Separately reject observation-after-ceiling and release-after-ceiling, including an in-range observation revised/released too late. Place each offending row after an otherwise valid row. The numeric spy records zero calls for the entire export. |
| Cutoff boundaries | The ceiling itself is allowed when all other conditions hold. Test future ASCII numeric-looking and deliberately unparseable tokens; both produce the clock failure before numeric processing. |
| Initial snapshot | Include old reference weeks tagged with the initial 2009-05-28 vintage and a following genuine release. Only the latter can become an eligible value. Excluded numeric-looking or malformed value tokens never convert and never enter the exclusion audit. |
| No fabricated first release | An old observation introduced as a backfill cannot be accepted just because it appears in a first-release-only export. The confirmed snapshot/eligibility rule determines exclusion; unresolved later backfill cases remain a reconciliation limitation rather than being “fixed” with an assumed weekly lag. |
| Duplicates and revisions | Reject duplicate reference-week rows, including conflicting values or multiple first-release dates; do not silently keep first/last/minimum. Also reject exact duplicate records. |
| Missing values and gaps | Under the confirmed policy, test the documented missing sentinel separately from blank/malformed values. Preserve explicit unavailable status and missing-week coverage; never fill, interpolate or shorten a consecutive-week requirement. |
| Numeric validity | Parameterized zero, negative, NaN, positive/negative infinity, malformed decimal and delimiter corruption fail. Exact admissible numeric syntax/precision follows the source schema, not permissive locale parsing. |
| Stable provenance | Every retained row and excluded-row audit links back to the same source ZIP/member and line identity. Counts reconcile all source records into retained, explicit-missing and clock-excluded categories without double counting. |

The 25 methods include compact parameterized cases where failures have the same contract. Tests target admission semantics rather than reproduce the earlier experiment-publication transaction suite or duplicate all symlink machinery.
