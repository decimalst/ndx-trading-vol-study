# Independent first-report ledger verification

Prospective design, 2026-09-08, before verifier implementation. This component owns only `src/verify_claims_release_ledger.py`, its separate synthetic test module and these design/test logs. It imports no producer ledger builder, repository source validator, feature or model routine. Standard-library date, URL and exact-schema checks independently reconstruct the ledger expected from the supplied pinned DOL and ALFRED records.

`verify_ledger(ledger, reports, alfred_records, start='2009-05-30', end='2025-10-18')` returns status `VERIFIED` plus requested bounds, reference-week count, status counts and input counts, or raises `ValueError`. It never mutates or repairs inputs. Bounds are literal Saturday dates within the default interval; smaller intervals support generated tests. Every supplied report and ALFRED record must lie inside the requested bounds. Out-of-bounds data, duplicates and malformed rows fail instead of being filtered. DOL release dates are unique; ALFRED release dates may repeat, as the documented March 2018 pair requires.

The independently required top-level ledger keys are `status`, `start`, `end`, `rows`, `counts`. The producer status is exactly `FIRST_REPORT_LEDGER_BUILT_NOT_INDEPENDENTLY_VERIFIED`. Each row has exactly `reference_week`, `release_date`, `first_report_value`, `status`, `source_url`, `release_text_sha256`, `source_comparison`. Rows enumerate every Saturday in chronological order. Status counts have exactly `observed`, `unresolved_correction`, `no_admitted_release`. The comparison has exactly `kind`, `dol_value`, `alfred_value`, `alfred_realtime_start_date`, `alfred_source_line`, `value_agrees`, `release_date_agrees`. Boolean and integer types are distinguished even where Python equality would otherwise conflate them.

All non-tail weeks require both sources. Ordinary weeks require equal original DOL and ALFRED values and displayed dates, retain the DOL value/provenance, and use kind `exact_agreement`. Only 2017-03-18 is `unresolved_correction`: supplied DOL 261000 on March 23 and ALFRED 258000 on March 23 must match the fixed disposition; the output value is null, DOL date/provenance remain, and comparison booleans are false/true. Only 2018-03-17 uses `documented_original_dol_disagreement`: original DOL 229000 on March 22 is retained against ALFRED 227000 on March 29, with false/false comparison booleans. These literal values come from the prior source disposition and are not fitted or selected by this verifier.

Only 2025-09-27, 2025-10-04, 2025-10-11 and 2025-10-18 are `no_admitted_release`. Each must be absent from both source inputs; release date, value, URL and text hash are null, comparison kind is `no_admitted_release`, and all other comparison fields are null. No missing interior week or invented tail report is accepted. The full intended inventory remains 856 Saturdays, 851 supported values, one unresolved value and four absent reports. Smaller requested intervals must enforce any fixed exception or tail week they contain.

DOL rows have the eight exact parsed-report fields and statistic `advance_seasonally_adjusted_initial_claims`; their week must be Saturday before the release date and their explicit body evidence must be exactly `[actual_release_date]` and boolean true. Supplied text hashes must be lowercase 64-digit hex. Official HTTPS identities are independently checked: matching calendar `oui.doleta.gov/press/YYYY/MMDDYY.asp|pdf`, the sole actual-2019-01-03 `010318.pdf` exception, or exact-host/path OPA numeric PDFs whose identifier starts with the release year. Query/fragment/port/user-info, alternate hosts, mismatched years and rolling URLs fail. Dates cannot exceed 2025-10-20. ALFRED inputs require their five exact source-record fields, an observed positive exact integer, source line at least two, Saturday reference week and a non-earlier literal realtime-start date. Missing input values cannot become admitted ledger values.

The checker establishes exact consistency with the supplied pinned source records and the already reviewed dispositions. It does not reopen PDFs, prove that a caller-supplied text hash authenticates bytes, rediscover the 2017 correction clock, or convert ALFRED's field into an ingestion timestamp. Root owns artifact hash binding and authentic input loading. No actual model, feature, market cohort or score is read. No existing code or first-pass evidence is changed.

Prewritten generated tests will independently supply literal ordinary, exception and gap ledgers. They cover independent reconstruction with reordered inputs; value/date/provenance corruption; hidden ALFRED substitution; wrong exception amounts/dates; unjustified missingness or corrections; all four explicit tail gaps; exact schema/types; invalid identities/body dates; duplicate/out-of-bounds source rows; chronological complete-grid enforcement; caller-bound mismatch; and input immutability. No producer builder supplies an expected result. RED and GREEN evidence is retained alongside this design before root uses the checker as a source boundary.

Completion evidence: the 19 generated test methods were written before the verifier module. LEDGER_VERIFICATION_RED.log records the actual missing-module import failure. The first implementation and the final run after formatting each passed all 19 tests in 0.002 seconds; LEDGER_VERIFICATION_GREEN.log and LEDGER_VERIFICATION_LINT.log retain the final pass and clean Ruff result. The output's exact keys are `status`, `start`, `end`, `reference_weeks`, `counts`, `reports_checked`, `alfred_records_checked`. The implementation did not call or import the producer ledger builder, including for its test expectations. No actual source ledger was constructed or checked by this agent; root owns the pinned real-input execution. No existing source/test file was edited.
