# Independent initial-claims release reconciliation

Prospective component, 2026-09-08. This design and the generated test file precede implementation. No actual release body, claims value, historical feature, fitted model or score has been inspected by this component. The code uses the primary Python environment and standard-library text/date/decimal-free integer logic only; root owns HTML/PDF extraction and authenticated acquisition.

`parse_release_text(text, release_date, source_url)` accepts extracted text, a literal ISO actual public-release date and an official dated `https://oui.doleta.gov/press/YYYY/MMDDYY.asp|pdf` identity. The date must agree with the URL and be on or before 2025-10-20. Query strings, fragments, user information, alternate hosts, ports and rolling URLs are not dated identities for this parser.

Exactly one clause must state: “In the week ending [Month day, optional year], the advance figure for seasonally adjusted initial claims was [count]”. Whitespace/case/extraction line breaks are normalized; positive plain integer counts and correctly grouped comma/space thousands are supported. Decimal, exponent, nonfinite, malformed, nonpositive, revised-figure, previous-week, continued-claims and unadjusted substitutions have no fallback. Multiple matching headlines, including duplicate identical headlines, are ambiguous and fail. Other genuine previous-week/revision/continued counts in the same release must not replace the headline.

An absent week year is derived from the release year, moving to the immediately previous year only when month/day would otherwise follow release. Only then is Saturday validated. The parser never searches older years for a convenient weekday. The week must be a valid date strictly before release. Wednesday releases are allowed. Recognized explicit For release, Release Date and embargoed-until header dates must agree with the supplied release date; an explicit weekday must also agree. Supported header absence is disclosed, not filled with the supplied metadata date.

The result has exact fields `statistic`, `observation_date`, `actual_release_date`, `value`, `source_url`, `release_text_sha256`, `body_release_dates`, and `body_release_date_verified`. The SHA-256 binds the original extracted UTF-8 text before whitespace normalization. The latter two fields distinguish actual body-date evidence from URL-bound metadata. This parser cannot authenticate acquisition or prove original website availability from caller-supplied strings alone.

`reconcile_reports(records, reports)` accepts root's five-field CSV records (`observation_date`, `alfred_realtime_start_date`, `value`, `status`, `source_line`) and these release records. It validates the whole input, rejects duplicate weeks/release dates and malformed records, and checks exact week membership, original release date and integer value. Missing CSV values remain unavailable; neither side silently fills or replaces the other. Every unmatched input and interior Saturday omitted on both sides is an explicit issue. The caller remains responsible for establishing intended endpoint coverage outside the supplied range.

The output fields are `status`, `records_count`, `reports_count`, `matched_count`, `matched`, and `issues`. Only an entirely covered, nonempty, exact match has status RECONCILED. Otherwise RECONCILIATION_MISMATCH lists missing/extra release, unavailable value, release-date/value mismatch, interior-week gap or empty-scope issues; matched rows are diagnostic partial matches, never a partially admitted panel. Both actual DOL release and ALFRED realtime-start fields remain separate even when equal. Neither is relabeled as a distinct ingestion timestamp.

Invented official-style examples cover old HTML-stripped/new PDF-extracted whitespace, separators, year rollover, Wednesday dates, exact numeric identity, revised/continued/unadjusted decoys, ambiguous headlines, malformed dates/counts, source-ceiling and dated-URL disagreement, absence/conflict of body-date evidence, two-sided coverage, omitted weeks, unavailable values and duplicated/malformed records. Expected values are literal fixtures; neither root's source parser nor its numeric conversion routine is imported. Actual missing-module RED and subsequent GREEN/lint results will be retained here before any real release-value reconciliation is authorized.
