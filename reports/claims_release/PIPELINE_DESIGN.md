# Prospective monthly claims pipeline

Generated tests precede the new implementation. No actual source values, market panels, support counts, models or scores are read or computed in this component task.

`build_panel(features, targets, config)` preserves the caller's full aligned native calendar. The 19 candidate inputs determine the common training and application cohort for every arm. All numeric inputs must be real finite values or explicit NaN; observed targets must be positive. The target endpoint must equal the fifth subsequent full-calendar session, with NaT at the final five origins. Every date is bounded by source_end and the immutable 2025-10-20 ceiling. Config contains ISO origin_start/end, nonoverlapping development/evaluation pairs, source_end and positive integer minimum_train/minimum_train_releases. Root binds production constants; generated fixtures use smaller windows and floors.

Each requested month refits on its first feature-complete origin, independent of query labels. Its training cutoff is the immediately previous full-calendar session, including a feature-incomplete session. Training uses all earlier common-complete origins with observed targets ending by that cutoff; distinct latest DOL release dates count release support. Any support, model or arithmetic failure aborts the call. The existing fixed three-arm OLS producer owns model math. All complete monthly applications are retained, including missing or phase-ineligible targets. Scored rows use finite QLIKE q/f-log(q/f)-1 without clipping. Development endpoints must mature by development end; evaluation endpoints by source_end, independently of evaluation origin end.

The exact five outputs are applications, panel, coverage, schedules (DataFrames) and fits (list). Applications columns: origin, fit_origin, training_cutoff, train_n, train_releases, claim_reference_week, claim_release_date, offset, phase, pred_market, pred_matched, pred_candidate. Panel columns: origin, model, prediction, y, loss, target_end, phase, claim_reference_week, claim_release_date, offset, fit_origin, training_cutoff, train_n, train_releases. Offset uses full-calendar position modulo five. Panel order is origin then market/matched/candidate; other frames are ascending origin or month. Frame dates are timestamps/NaT; fit audit dates are ISO strings.

Coverage columns: origin, phase, feature_complete, missing_features, claim_status, claim_reference_week, claim_release_date, offset, target_end, target_observed, target_within_phase, scored, status, fit_origin, training_cutoff. Missing feature names are pipe-separated in fixed ALL order. Status precedence: incomplete_features, outside_phase, target_not_mature (NaT endpoint), missing_target, target_after_phase_cutoff, scored. Phase is development, evaluation or outside_phase. Incomplete origins have NaT fit linkage. Target-observed means finite positive y; target-within-phase means known endpoint within the applicable development/source fence.

Schedule columns: month, status, fit_origin, training_cutoff, requested_n, application_n, train_n, train_releases. Every requested civil month is included. Status is fitted, no_complete_origin or no_requested_origins. No-fit dates are NaT, training counts are null, application_n is zero and requested_n is the actual requested calendar count. Entirely empty application cohorts remain explicit empty outputs and coverage; root's prospective aggregate support gate determines their disposition.

Each fitted audit contains month, fit_origin, training_cutoff, complete train_origins/application_origins, train_n, train_releases, and model_audits verbatim from the fixed OLS producer. Tests independently specify maturity boundaries and common cohorts, perturb unavailable future labels, preserve full-calendar offsets, test all missingness reasons, force support/arithmetic failures, and integrate the three real model arms on invented data. Independent verification is a separate component with no producer imports.
