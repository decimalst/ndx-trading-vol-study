# Generated publication transaction contracts

These tests are written before `peak_age_search.run` is implemented. Every
test uses a disposable directory containing generated code, protocol, documentary
pins, table fixtures and ledger rows. Source admission is always mocked. There
are no historical source reads, model fits, support counts or scores.

The runner must register all three peak_age/baseline, peak_age/depth and
peak_age/mean horizon21 hypotheses before input enumeration or admission. It
then records137 canonical inherited rows; successful and ordinary failed
attempts contain143 events. Missing inheritance remains explicitly unavailable.
Pretest or freeze failure precedes registration and numerical access.

Generated successful output contains exactly eight data files: upstream_admission
JSON, feature/target/feature-state/forecast/application-state Parquet tables,
fit JSON and support-audit JSON; the report metrics and ledger complete the
ten-output contract. Complete issued applications include an unscored query.

The manifest binds all new and old Python files, exact input pins, unrelated old
reports and protocols. Tests mutate each category, add a new Python file, alter
the protocol/design/full-suite evidence, and inject source/support/fit/scoring,
report and ledger failures. Canonical terminal failures retain all three p1
rows. Scored-but-unpublished metrics remain separately marked ineligible for
inheritance or promotion. Interrupted ledger bytes are retained before atomic
canonical recovery. Existing canonical attempt/proof/metrics files, private
outputs and dangling marker links cannot be overwritten.

The final boundary independently requires exact old wave20 failure/metrics/proof
pins and latest wave21 metrics/proof/publication pins after the last general
hash loop. Removing a required pin from the manifest is a failure. Tests inject
mutations/deletions after the general pass and both real and dangling-symlink
failure markers during the final required-pin hashing. Current/index-hinge and
successful wave18/19/21 failure markers must remain absent before and after
these final checks. The identified old failed family stays byte-exact and does
not become a global obstacle to the new registered trial.

No incomplete, duplicated or foreign contrast family may publish. All failure
assertions check full ledger ordering, cumulative140 accounting, canonical
metrics/failure equality, empty phases and leads, and all three adjusted p1s.

The initial21 tests recorded missing-run/API RED before transaction
implementation. A twenty-second pre-empirical test was added afterward to
inject a late current failure symlink pointing at an existing sentinel. It
requires unchanged sentinel bytes and a regular canonical failure record;
its first execution is not presented as preimplementation RED.

Four additional prefreeze regression methods inject symlinks to existing
sentinels immediately before writes to pre-run evidence, successful/failure
results prose, each of the five Parquet outputs, and interrupted-ledger backup.
They require untouched sentinel bytes and regular output paths. Failure cases
still recover the complete canonical143-event ledger and three p1 rows; the
interrupted backup preserves the exact pre-failure140 events. These tests are
run against the existing direct writers before their proposed atomic-write
repair, with separate OUTPUT_WRITES_RED/GREEN evidence. All cases use generated
temporary files; this extends transaction coverage without changing the model,
features, protocol, thresholds or experiment scope.

failures across the four new methods before the writer change. Root then
